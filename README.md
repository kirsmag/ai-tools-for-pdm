# Кто выгуливает Бориса

Учебный micro-MVP для записи сотрудников на прогулку с Борисом и отображения последнего кормления. Компания и все данные в проекте вымышленные; используйте только синтетические ФИО.

## Состояние проекта

Сейчас доступны локальный сервер, общая страница сегодняшних слотов, запись на свободный слот и форма отметки кормления. Все записи хранятся в SQLite. План работ находится в [PLAN.md](PLAN.md).

## Локальный запуск

Требуется Node.js 22.13.0 или новее. В папке проекта выполните:

```sh
npm start
```

Сервер слушает `http://127.0.0.1:3000`; страница доступна по адресу `http://127.0.0.1:3000/`, а проверочный маршрут — `/health`. При первом запуске создаётся `boris.sqlite` в папке проекта. Этот SQLite-файл содержит пользовательское состояние и не включается в Git.

## Сценарий

На общей странице сотрудник видит текущую дату и пять слотов на сегодня: 09:00, 11:00, 13:00, 15:00 и 17:00. Для свободного слота можно выбрать время, ввести синтетическое ФИО и подтвердить запись. Сервер атомарно занимает свободный слот; повторная попытка получает конфликт, не меняя исходное ФИО. Запись сохраняется в SQLite.

Карточка показывает ФИО и время последнего кормления. Формой рядом с карточкой можно добавить новую отметку по синтетическому ФИО; после сохранения карточка обновляется.

## Техническая основа

- Node.js 22.13.0 или новее и npm; запуск командой `npm start`.
- SQLite-файл в папке проекта для записей прогулок и кормлений.
- Пять фиксированных слотов создаются для текущей даты, если их ещё нет.
- Занять можно только свободный слот; серверная запись должна быть атомарной.
- Интерфейс должен оставаться читаемым на широком и узком экране.

## Границы

Это учебный micro-MVP, а не внутренняя или промышленная система. В проект не входят:

- регистрация, авторизация, корпоративный SSO, роли и справочник 111 сотрудников;
- отмена и администрирование записей, уведомления, календарь на неделю и история всех действий;
- несколько собак, несколько независимых сценариев или второй MVP;
- реальные ФИО, рабочие данные, секреты и внешние интеграции;
- ручное проектирование базы данных как отдельная учебная задача;
- масштабирование, собственная инфраструктура, production-grade надёжность и обещание промышленной готовности;
- обязательный деплой, выбор хостинга или инструкция по публикации.

## Критерии результата

Результат сверяется с семью критериями из `spec.md`: текущая дата и ровно пять слотов; различимое состояние слотов и ФИО записавшегося; успешная запись; серверный отказ при повторной записи без перезаписи исходных данных; сохранение в SQLite; обновление карточки кормления; работоспособность главного сценария на широком и узком экране.

Контролируемый smoke-check из `spec.md` пройден: пользователь подтвердил читаемость на широком и узком экране, отказ при повторной записи, отображение карточки кормления и отсутствие ошибок в консоли браузера; серверные проверки подтвердили атомарность и сохранение данных в SQLite.

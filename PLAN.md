# План выполнения

План охватывает только учебный micro-MVP из `spec.md`. Статус фиксируется по фактическому результату; неизвестная или непроверенная работа не отмечается как завершённая.

## Этапы

| Этап | Работа | Проверка / критерий приёмки | Статус |
|---|---|---|---|
| 1. Основа приложения | Подготовить минимальный Node.js/npm-проект, локальный запуск и SQLite-файл в папке проекта. Реализовать указанную в `spec.md` схему и создание пяти слотов на текущую дату. | Приложение запускается локально; на текущую дату доступны ровно пять слотов, изначально свободных. | Выполнен |
| 2. Просмотр состояния | Создать общую страницу с текущей датой, состояниями пяти слотов и карточкой последнего кормления. | Дата и ровно пять фиксированных времени видны; занятые слоты показывают ФИО; карточка кормления показывает время и ФИО, если кормление отмечено. | Выполнен, подтверждён пользователем |
| 3. Запись на прогулку | Добавить ввод непустого после обрезки пробелов синтетического ФИО и серверную атомарную запись только в свободный слот. | Свободный слот можно занять; повторная попытка получает понятный конфликт, первоначальное ФИО не меняется. | Выполнен, проверен пользователем |
| 4. Отметка кормления | Добавить возможность отметить кормление с синтетическим ФИО и обновлять карточку последнего кормления. | После отметки карточка показывает новое время и ФИО. | Выполнен, проверен пользователем |
| 5. Адаптивность и итоговая проверка | Обеспечить читаемость главного сценария на широком и узком экране. После последнего изменения выполнить контролируемый smoke-check из `spec.md`. | Фактически пройдены все семь DoD; smoke-check включает запись, конфликт, сохранение после обновления/во втором браузере, отметку кормления и оба размера экрана. | Выполнен, проверен пользователем |

## Журнал проверок

Этап 1: `npm start` запустил сервер; запрос `GET /health` вернул HTTP 200 и JSON со статусом `ok` и пятью инициализированными слотами. Проверка SQLite подтвердила наличие таблиц `walk_slots` и `feedings` и пяти свободных слотов на `2026-10-17`.

Этап 2: проверка синтаксиса `server.js` и `public/app.js` прошла. Локальный `GET /` вернул HTML страницы, `GET /api/today` вернул текущую дату, пять состояний из SQLite и `lastFeeding: null`; `GET /styles.css` и `GET /app.js` вернули клиентские ресурсы. Пользователь подтвердил отображение страницы и перешёл к этапу 3. Полный smoke-check приложения не выполнялся.

Этап 3: проверка синтаксиса `server.js` и `public/app.js` прошла. На изолированной временной копии первая запись синтетического ФИО вернула HTTP 201 и сохранила имя после удаления крайних пробелов. Повторная запись того же слота вернула HTTP 409; последующий `GET /api/today` подтвердил, что исходное ФИО осталось в SQLite. Пользователь проверил повторную попытку через две вкладки: сообщение об отказе появилось.

Этап 4: проверка синтаксиса `server.js` и `public/app.js` прошла. На изолированной временной копии `POST /api/feedings` с синтетическим ФИО вернул HTTP 201, обрезал крайние пробелы и сохранил имя со временем; последующий `GET /api/today` вернул эту запись в `lastFeeding`. Пользователь подтвердил, что карточка показывает данные кормления.

Этап 5: для узких карточек слотов введена трёхколоночная сетка и перенос длинного ФИО. На свежей временной копии проверен серверный smoke-check: API вернул текущую дату и пять слотов; первая запись вернула HTTP 201; повторная попытка вернула HTTP 409; исходное имя не изменилось; отметка кормления вернула HTTP 201 и появилась в `lastFeeding`; обе записи сохранились после перезапуска сервера. Синтаксис клиентского и серверного JS прошёл проверку. Пользователь подтвердил читаемость на широком и узком экране, появление отказа при повторной записи, отображение последнего кормления и отсутствие ошибок в консоли браузера. Рабочая SQLite-база проекта тестовыми данными не изменялась. Контролируемый smoke-check завершён; семь DoD подтверждены.

## Ограничения скоупа

Не добавлять регистрацию, авторизацию, корпоративный SSO, роли или справочник сотрудников; отмену и администрирование записей, уведомления, недельный календарь или историю действий; несколько собак, независимые сценарии или второй MVP; реальные ФИО, рабочие данные, секреты или внешние интеграции; отдельное ручное проектирование БД; масштабирование, собственную инфраструктуру или production-grade обещания. Деплой, выбор хостинга и инструкция по публикации не являются обязательной частью проекта.
